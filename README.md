# Student Activity SQL Analytics

Аналитический проект по исследованию активности и результатов обучения пользователей корпоративного клиента.

В рамках проекта с помощью PostgreSQL были рассчитаны показатели успеваемости пользователей, активности по месяцам и сложности заданий. После этого результаты были визуализированы в Metabase.


## Цель проекта

Основная цель проекта — проанализировать обучение пользователей одного корпоративного клиента и ответить на несколько вопросов:

- какие пользователи показывают наиболее высокую успешность при выполнении заданий;
- какие задания вызывают наибольшее количество ошибок;
- в какие месяцы наблюдается максимальная активность пользователей;
- какие показатели можно использовать для дальнейшего анализа качества обучения.

Проект построен не просто как набор SQL-запросов, а как небольшой аналитический кейс: от получения данных и расчёта показателей до их интерпретации и визуализации.

## Данные

В анализе используются несколько связанных таблиц:

- `users` — информация о пользователях;
- `coderun` — попытки выполнения заданий;
- `codesubmit` — результаты решений;
- `userentry` — события активности пользователей.

Анализ проводится для пользователей одного корпоративного клиента:

```sql
where u.company_id = 1
```

## Структура анализа

Основной SQL-запрос построен через несколько CTE.

### 1. `first_data_users`

На первом этапе формируется выборка пользователей нужного корпоративного клиента и подготавливаются данные, которые используются дальше.

```sql
with first_data_users as (
    select
        u.id,
        u.username,
        u.company_id,
        concat_ws(' ', u.first_name, u.last_name) full_name,
        c.problem_id,
        c.is_false
    from users u
    left join codesubmit c
        on u.id = c.user_id
    where u.company_id = 1
)
```

Если у пользователя отсутствуют имя и фамилия, в итоговой выдаче используется `username`.

```sql
case
    when full_name is null or full_name = ''
        then username
    else full_name
end as "Имя"
```

## Анализ успеваемости пользователей

Для каждого пользователя рассчитываются:

- количество попыток;
- количество неправильно решённых задач;
- количество правильно решённых задач;
- процент правильных решений.

Основная часть расчёта:

```sql
count(c.id) as "Кол-во прокруток запроса",

count(
    case
        when is_false = 1 then 1
    end
) as "Кол-во неправильно решенных задач",

count(
    case
        when is_false = 0 then 1
    end
) as "Кол-во правильно решенных задач"
```

Процент успешных решений рассчитывается следующим образом:

```sql
round(
    count(
        case
            when is_false = 0 then 1
        end
    ) * 100.0
    / nullif(count(c.id), 0),
    2
) as "% Правильно решенных задач"
```

`NULLIF` используется для защиты от деления на ноль.

Полный CTE:

```sql
data_resh as (
    select
        f.id,

        case
            when full_name is null or full_name = ''
                then username
            else full_name
        end as "Имя",

        count(c.id) "Кол-во прокруток запроса",

        count(
            case
                when is_false = 1 then 1
            end
        ) "Кол-во неправильно решенных задач",

        count(
            case
                when is_false = 0 then 1
            end
        ) "Кол-во правильно решенных задач",

        round(
            count(
                case
                    when is_false = 0 then 1
                end
            ) * 100.0
            / nullif(count(c.id), 0),
            2
        ) "% Правильно решенных задач"

    from first_data_users f

    left join coderun c
        on c.user_id = f.id

    group by
        "Имя",
        f.id

    order by
        "% Правильно решенных задач" desc
)
```

## Рейтинг пользователей

После расчёта успеваемости формируется Top-5 пользователей по проценту правильных решений.

Для ранжирования используется оконная функция:

```sql
ROW_NUMBER() OVER (
    ORDER BY "% Правильно решенных задач" DESC
)
```

CTE рейтинга:

```sql
data_resh_5 as (
    select
        ROW_NUMBER() OVER (
            ORDER BY "% Правильно решенных задач" DESC
        ) n,

        "Имя",
        "% Правильно решенных задач"

    from data_resh

    where "% Правильно решенных задач" is not null
      and "% Правильно решенных задач" < 100

    limit 5
)
```

### Почему исключены некоторые результаты со 100%

В исходных данных встречаются пользователи, которые совершили только одну попытку, сразу решили задачу правильно и после этого больше не проявляли активности.

Например:

```text
1 правильное решение / 1 попытка = 100%
```

Формально такой пользователь показывает максимальный процент правильных решений, но сравнивать его с пользователем, который выполнил большое количество заданий и имеет высокий процент успешности, не совсем корректно.

Поэтому в текущей версии проекта была добавлена фильтрация:

```sql
and "% Правильно решенных задач" < 100
```

Это позволяет убрать часть пользователей, у которых высокий процент получен на слишком маленьком количестве наблюдений.

При дальнейшем развитии проекта эту логику можно сделать точнее: вместо исключения всех значений `100%` добавить минимальное количество попыток для попадания пользователя в рейтинг.

Например:

```sql
having count(c.id) >= 5
```

Так можно будет оставить пользователей с реальными 100% результатами при достаточном количестве выполненных заданий.

## Анализ проблемных заданий

Следующая часть проекта — поиск заданий, в которых пользователи чаще всего совершают ошибки.

Для каждого задания рассчитывается количество неправильных решений:

```sql
count(
    case
        when is_false = 1 then 1
    end
) as cnt_error
```

После этого задания сортируются по количеству ошибок и формируется Top-5.

```sql
zad_error as (
    select
        ROW_NUMBER() OVER (
            ORDER BY count(
                case
                    when is_false = 1 then 1
                end
            ) DESC
        ) AS n,

        problem_id,

        count(
            case
                when is_false = 1 then 1
            end
        ) cnt_error

    from codesubmit c

    join users u
        on u.id = c.user_id

    where company_id = 1

    group by problem_id

    order by cnt_error desc

    limit 5
)
```

Этот показатель позволяет определить задания, на которых пользователи сталкиваются с наибольшим количеством ошибок.

При этом большое количество ошибок само по себе ещё не доказывает, что задание является слишком сложным.

Высокое значение может быть связано, например, с большим количеством попыток.

Поэтому следующим шагом анализа можно дополнительно рассчитать:

```text
Error Rate =
Количество ошибочных решений /
Количество всех попыток
```

Также можно посмотреть:

- количество уникальных пользователей, решавших задачу;
- среднее количество попыток до успешного решения;
- долю пользователей, которые вообще смогли решить задачу.


## Анализ активности пользователей

Для оценки активности пользователей анализируется количество уникальных активных пользователей по месяцам.

Количество активных пользователей:

```sql
count(distinct u.user_id)
```

Дата события переводится на уровень месяца:

```sql
to_char(entry_at, 'YYYY-MM')
```

После этого формируется Top-5 месяцев с максимальной активностью.

```sql
activ_date as (
    select
        ROW_NUMBER() OVER (
            ORDER BY count(distinct u.user_id) DESC
        ) AS n,

        to_char(entry_at, 'YYYY-MM') mons,

        count(distinct u.user_id) act_cnt

    from userentry u

    join users u2
        on u2.id = u.user_id

    where u2.company_id = 1

    group by
        to_char(entry_at, 'YYYY-MM')

    order by
        act_cnt desc

    limit 5
)
```

Такой анализ позволяет понять, в какие периоды количество активных пользователей было максимальным.

При этом сам SQL показывает только факт изменения активности, но не объясняет его причину.

Чтобы понять, почему в конкретном месяце пользователи были более или менее активны, дополнительно потребовались бы данные о:

- начале и окончании обучения;
- дедлайнах;
- запуске новых модулей;
- обязательных заданиях;
- изменениях программы курса.

## Итоговая выдача

В проекте рассчитываются три независимых Top-5 показателя:

1. пользователи по успешности;
2. задания по количеству ошибок;
3. месяцы по активности.

Чтобы вывести их в одной компактной таблице для последующей визуализации, каждому Top-5 присваивается номер строки через `ROW_NUMBER()`.

После этого результаты объединяются по позиции в рейтинге:

```sql
select
    "Имя",
    "% Правильно решенных задач",
    problem_id "ID задачи",
    cnt_error "Количество ошибок в задаче",
    mons "Месяц",
    act_cnt "Количество заходов уникальных пользователей"

from data_resh_5 d

full join zad_error z
    on z.n = d.n

full join activ_date a
    on a.n = d.n
```

Важно: `n` здесь не является бизнес-ключом между пользователем, задачей и месяцем.

Он используется только как технический способ расположить три независимых Top-5 списка рядом в одной итоговой выдаче.

То есть:

```text
пользователь №1 в рейтинге
задача №1 в рейтинге
месяц №1 в рейтинге
```

не связаны между собой по смыслу.

Такое объединение используется исключительно для компактного представления результатов и последующей визуализации в Metabase.

## Основные выводы

### Успеваемость пользователей

Рейтинг позволяет выделить пользователей, которые показывают высокий процент правильных решений.

При этом одного процента недостаточно для окончательной оценки пользователя.

Для более точного анализа также стоит учитывать:

- количество выполненных заданий;
- количество попыток;
- регулярность активности;
- динамику результатов;
- сложность выполненных заданий.

Таким образом, высокий процент правильных решений можно использовать как один из сигналов для дальнейшего анализа, но не как единственный показатель качества пользователя.


### Проблемные задания

Top-5 по количеству ошибок позволяет быстро определить задания, которые требуют дополнительного внимания.

Для таких заданий можно дополнительно проверить:

- насколько понятно сформулировано условие
- достаточно ли обучающих материалов
- соответствует ли сложность задания текущему этапу обучения
- сколько попыток в среднем требуется пользователю для успешного решения.

После дополнительного анализа можно принимать решение о необходимости изменения инструкции, обучающих материалов или сложности задания.


### Активность пользователей

Анализ активности позволяет увидеть периоды, когда количество уникальных активных пользователей было максимальным.

Сам показатель показывает, **когда** произошёл рост или спад активности, но не объясняет, **почему** он произошёл.

Для определения причин можно сопоставить активность с:

- расписанием обучения;
- дедлайнами;
- датами запуска новых модулей;
- обязательными заданиями;
- изменениями программы.
